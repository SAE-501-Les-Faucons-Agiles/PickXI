Architecture & Documentation

Spécifications techniques pour la SAÉ BUT3 5.Real.01 (IUT de Villetaneuse).

Architecture MVC Découplée

Modèles (M)

app/models/player_model.py : Définition des structures Player, PlayerFilter, RankedPlayer et PerformanceMetrics.

Vues (V)

Templates Jinja2 dans app/templates/ avec layout split-view (joueurs à gauche, tableau de bord des métriques à droite).

Contrôleurs (C)

app/controllers/ : Contrôleur web home_controller.py et contrôleur API REST api_controller.py.

Les Deux Approches Algorithmiques

1. Similarité Vectorielle O(N * D)

Projette les statistiques de chaque joueur (PAC, SHO, PAS, DRI, DEF, PHY, WF) dans un espace euclidien normalisé et calcule la distance cosinus avec le profil de recherche souhaité.

2. Graphe Collectif & Rentabilité O(N * C + N log K)

Évalue le réseau de synergie d'équipe (points de collectif club, nation, ligue) et applique une heuristique qualité/prix pour maximiser la rentabilité en crédits.

Source des Données (Kaggle)

L'application est conçue pour exploiter le dataset Kaggle : FC 26 FIFA 26 Player Data (rovnez) .

Pour charger l'intégralité du dataset Kaggle (+18 000 joueurs) :
Déposez simplement votre fichier CSV dans le dossier data/ (ex: data/players.csv). Le dépôt le détecte et le parse automatiquement au démarrage.
